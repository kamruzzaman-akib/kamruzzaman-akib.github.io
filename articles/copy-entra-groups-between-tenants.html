PowerShell & Microsoft 365

Copy Entra ID groups to another tenant with PowerShell (export, import and clean-up)

Three Microsoft Graph PowerShell scripts for a tenant-to-tenant move: export every group to CSV, recreate them in the new tenant with a dry run and an old-to-new ID map, and delete a group by ID when you need to clean up.

By Kamruzzaman Akib · 5 min read

  • PowerShell
  • Microsoft Graph
  • Entra ID
  • Intune
  • Tenant migration
About this article. I wrote the scripts in this article for my day-to-day admin work. The public versions have personal file paths removed and were tidied for sharing, and examples use Microsoft’s fictional contoso.com domain. As with any admin script, try it in a test or non-production tenant before you rely on it.

In a tenant-to-tenant migration, the groups that Intune apps, configuration profiles and licences are assigned to have to exist in the new tenant before you can assign anything. Rebuilding dozens of them by hand is slow and easy to get wrong, so I scripted it: one script exports the groups from the source tenant, a second recreates them in the destination tenant, and a third deletes a group by ID when you need to tidy up after a test run.

What gets copied

Copied: name, description, mail nickname, group type (security or Microsoft 365), visibility, and the membership rule of dynamic groups.

Not copied: members, owners, and the Intune or licence assignments themselves. Distribution lists and mail-enabled security groups are skipped too, because Microsoft Graph can only create security groups and Microsoft 365 groups. Create those in Exchange Online instead (see Bulk create distribution groups in Exchange Online).

What you need

  • The Microsoft Graph PowerShell SDK: Install-Module Microsoft.Graph -Scope CurrentUser.
  • In the source tenant, an account that can read groups (permission Group.Read.All).
  • In the destination tenant, an account allowed to create groups, for example a Groups Administrator (permission Group.ReadWrite.All).

Step 1: Export the groups from the source tenant

Export-EntraGroups.ps1In the script libraryDownload
Show the full script (57 lines)
<#
.SYNOPSIS
    Exports Microsoft Entra ID groups (the groups Intune apps and policies are assigned to)
    to a CSV file, so they can be recreated in another tenant.

.DESCRIPTION
    First half of a tenant-to-tenant group copy. For each group it saves the name,
    description, mail nickname, group type, visibility and, for dynamic groups, the
    membership rule. Import-EntraGroups.ps1 reads this file in the destination tenant.

    Members, owners and assignments are not exported.

.PARAMETER OutputPath
    Where to save the CSV file. Default: groups.csv in the current folder.

.EXAMPLE
    .\Export-EntraGroups.ps1 -OutputPath .\groups.csv

.NOTES
    Author      : Kamruzzaman Akib
    Modules     : Microsoft.Graph.Authentication, Microsoft.Graph.Groups
    Permissions : Group.Read.All (delegated)
    Sign in to the SOURCE tenant when prompted.
#>
#Requires -Modules Microsoft.Graph.Authentication, Microsoft.Graph.Groups

[CmdletBinding()]
param(
    [string]$OutputPath = '.\groups.csv'
)

Connect-MgGraph -Scopes 'Group.Read.All' -NoWelcome -ErrorAction Stop
Write-Host "Connected to tenant $((Get-MgContext).TenantId)" -ForegroundColor Cyan

$properties = 'Id', 'DisplayName', 'Description', 'MailNickname', 'MailEnabled', 'SecurityEnabled',
              'GroupTypes', 'Visibility', 'MembershipRule', 'MembershipRuleProcessingState'

$groups = @(Get-MgGroup -All -Property $properties -ErrorAction Stop)

$groups | ForEach-Object {
    [PSCustomObject]@{
        ObjectId                      = $_.Id
        DisplayName                   = $_.DisplayName
        Description                   = $_.Description
        MailNickname                  = $_.MailNickname
        MailEnabled                   = $_.MailEnabled
        SecurityEnabled               = $_.SecurityEnabled
        GroupTypes                    = $_.GroupTypes -join ';'
        Visibility                    = $_.Visibility
        MembershipRule                = $_.MembershipRule
        MembershipRuleProcessingState = $_.MembershipRuleProcessingState
    }
} | Export-Csv -Path $OutputPath -NoTypeInformation -Encoding UTF8

Write-Host "Exported $($groups.Count) groups to $((Resolve-Path -Path $OutputPath).Path)" -ForegroundColor Green

Disconnect-MgGraph | Out-Null
.\Export-EntraGroups.ps1 -OutputPath .\groups.csv

Sign in with your source-tenant account. The script prints the tenant ID it connected to, so you can check you’re in the right place before anything else happens.

Step 2: Review the CSV

  • Delete the rows for groups you don’t want to bring across, such as old test groups or groups that will arrive another way (for example, synced from on-premises Active Directory).
  • Check the dynamic membership rules. A rule that uses a custom directory extension (extension_<app ID>_…) points at an app in the old tenant and has to be rewritten.
  • Mail nicknames of Microsoft 365 groups must be unique in the destination tenant.

Step 3: Recreate the groups in the destination tenant

Import-EntraGroups.ps1In the script libraryDownload
Show the full script (124 lines)
<#
.SYNOPSIS
    Recreates Microsoft Entra ID groups from a CSV made by Export-EntraGroups.ps1.

.DESCRIPTION
    Second half of a tenant-to-tenant group copy. Run it while signed in to the
    DESTINATION tenant. For each row it creates a security group or Microsoft 365
    group with the same name, description, mail nickname, visibility and (for
    dynamic groups) membership rule.

    It skips:
      - groups whose name already exists in the destination tenant, so the script
        is safe to run again;
      - distribution lists and mail-enabled security groups, because Microsoft Graph
        cannot create them (create them in Exchange Online instead).

    It also writes <CsvPath>-id-map.csv with the old and new group IDs, which helps
    when you recreate Intune assignments.

    Run it with -WhatIf first to see what would be created.

.PARAMETER CsvPath
    Path to the CSV file created by Export-EntraGroups.ps1.

.EXAMPLE
    .\Import-EntraGroups.ps1 -CsvPath .\groups.csv -WhatIf

.EXAMPLE
    .\Import-EntraGroups.ps1 -CsvPath .\groups.csv

.NOTES
    Author      : Kamruzzaman Akib
    Modules     : Microsoft.Graph.Authentication, Microsoft.Graph.Groups
    Permissions : Group.ReadWrite.All (delegated)
    Members and owners are not copied.
#>
#Requires -Modules Microsoft.Graph.Authentication, Microsoft.Graph.Groups

[CmdletBinding(SupportsShouldProcess)]
param(
    [Parameter(Mandatory)]
    [ValidateScript({ Test-Path -Path $_ -PathType Leaf })]
    [string]$CsvPath
)

$rows = @(Import-Csv -Path $CsvPath)
if ($rows.Count -eq 0) {
    throw "The CSV file '$CsvPath' is empty."
}

Connect-MgGraph -Scopes 'Group.ReadWrite.All' -NoWelcome -ErrorAction Stop
Write-Host "Connected to tenant $((Get-MgContext).TenantId)" -ForegroundColor Cyan

$created = 0; $skipped = 0; $failed = 0
$idMap = New-Object System.Collections.Generic.List[object]

foreach ($row in $rows) {
    $name = $row.DisplayName
    if (-not $name) { continue }

    $groupTypes      = @($row.GroupTypes -split ';' | Where-Object { $_ })
    $mailEnabled     = ($row.MailEnabled -eq 'True')
    $securityEnabled = ($row.SecurityEnabled -eq 'True')

    # Microsoft Graph can only create Microsoft 365 groups and security groups.
    if ($mailEnabled -and ($groupTypes -notcontains 'Unified')) {
        Write-Warning "Skipped '$name': distribution lists and mail-enabled security groups must be created in Exchange Online."
        $skipped++
        continue
    }

    # Do not create a second group with the same name.
    $filterName = $name -replace "'", "''"
    $existing = Get-MgGroup -Filter "displayName eq '$filterName'" -Top 1 -ErrorAction SilentlyContinue
    if ($existing) {
        Write-Host "Skipped '$name': a group with this name already exists." -ForegroundColor DarkGray
        $skipped++
        continue
    }

    # Mail nickname is required. Make one from the name if the CSV has none.
    $mailNickname = $row.MailNickname
    if (-not $mailNickname) {
        $mailNickname = ($name -replace '[^a-zA-Z0-9]', '')
        if (-not $mailNickname) { $mailNickname = 'group' + (Get-Random -Maximum 999999) }
    }

    $params = @{
        DisplayName     = $name
        MailNickname    = $mailNickname
        MailEnabled     = $mailEnabled
        SecurityEnabled = $securityEnabled
    }
    if ($groupTypes.Count -gt 0) { $params.GroupTypes = $groupTypes }
    if ($row.Description -and $row.Description -ne '.') { $params.Description = $row.Description }
    if ($row.Visibility) { $params.Visibility = $row.Visibility }
    if ($row.MembershipRule) {
        $params.MembershipRule = $row.MembershipRule
        $params.MembershipRuleProcessingState = if ($row.MembershipRuleProcessingState) { $row.MembershipRuleProcessingState } else { 'On' }
    }

    if ($PSCmdlet.ShouldProcess($name, 'Create group')) {
        try {
            $newGroup = New-MgGroup @params -ErrorAction Stop
            Write-Host "Created '$name' ($($newGroup.Id))" -ForegroundColor Green
            $idMap.Add([PSCustomObject]@{ DisplayName = $name; OldId = $row.ObjectId; NewId = $newGroup.Id })
            $created++
        } catch {
            Write-Warning "Failed to create '$name': $($_.Exception.Message)"
            $failed++
        }
    }
}

if ($idMap.Count -gt 0) {
    $mapPath = [System.IO.Path]::ChangeExtension((Resolve-Path -Path $CsvPath).Path, $null).TrimEnd('.') + '-id-map.csv'
    $idMap | Export-Csv -Path $mapPath -NoTypeInformation -Encoding UTF8
    Write-Host "Old and new group IDs saved to $mapPath" -ForegroundColor Cyan
}

Write-Host ''
Write-Host "Done. Created: $created   Skipped: $skipped   Failed: $failed" -ForegroundColor Cyan

Disconnect-MgGraph | Out-Null

Sign in with your destination-tenant account and do a dry run first. Nothing is created; you see a “What if” line for each group:

.\Import-EntraGroups.ps1 -CsvPath .\groups.csv -WhatIf

Then run it for real:

.\Import-EntraGroups.ps1 -CsvPath .\groups.csv
  • Groups whose name already exists are skipped, so you can safely run it again after fixing a problem.
  • It saves groups-id-map.csv with each group’s old and new ID. Keep it: you need it when you recreate Intune assignments or update anything that refers to a group by ID.
  • When an admin creates a Microsoft 365 group, Graph adds that admin as an owner automatically; security groups get no owner. Review owners afterwards.

Step 4: Clean up a group by ID (if you need to)

Remove-EntraGroup.ps1In the script libraryDownload
Show the full script (64 lines)
<#
.SYNOPSIS
    Deletes a Microsoft Entra ID group by its object ID.

.DESCRIPTION
    Handy for cleaning up after a test import, or for removing a group straight
    through Microsoft Graph when the admin centre is slow or unhelpful.
    It looks the group up first, shows its name and asks you to confirm.
    Use -Force to skip the confirmation prompt (for example, in a loop).

    Microsoft 365 groups can be restored for 30 days after deletion.
    Treat any other group type as permanently deleted.

.PARAMETER GroupId
    Object ID of the group, as shown in the Entra or Intune admin centre.

.PARAMETER Force
    Delete without asking for confirmation.

.EXAMPLE
    .\Remove-EntraGroup.ps1 -GroupId 3f2a6b1c-0d4e-4f5a-9b8c-7d6e5f4a3b2c

.EXAMPLE
    .\Remove-EntraGroup.ps1 -GroupId 3f2a6b1c-0d4e-4f5a-9b8c-7d6e5f4a3b2c -WhatIf

.NOTES
    Author      : Kamruzzaman Akib
    Modules     : Microsoft.Graph.Authentication, Microsoft.Graph.Groups
    Permissions : Group.ReadWrite.All (delegated)
#>
#Requires -Modules Microsoft.Graph.Authentication, Microsoft.Graph.Groups

[CmdletBinding(SupportsShouldProcess, ConfirmImpact = 'High')]
param(
    [Parameter(Mandatory, HelpMessage = 'Object ID of the group to delete')]
    [ValidatePattern('^[0-9a-fA-F]{8}-([0-9a-fA-F]{4}-){3}[0-9a-fA-F]{12}$')]
    [string]$GroupId,

    [switch]$Force
)

if ($Force -and -not $PSBoundParameters.ContainsKey('Confirm')) {
    $ConfirmPreference = 'None'
}

Connect-MgGraph -Scopes 'Group.ReadWrite.All' -NoWelcome -ErrorAction Stop

try {
    $group = Get-MgGroup -GroupId $GroupId -Property Id, DisplayName, GroupTypes -ErrorAction Stop
} catch {
    Write-Error "No group found with ID $GroupId. $($_.Exception.Message)"
    return
}

$kind = if ($group.GroupTypes -contains 'Unified') { 'Microsoft 365 group' } else { 'group' }

if ($PSCmdlet.ShouldProcess("$($group.DisplayName) ($GroupId)", "Delete $kind")) {
    try {
        Remove-MgGroup -GroupId $GroupId -Confirm:$false -ErrorAction Stop
        Write-Host "Deleted $kind '$($group.DisplayName)' ($GroupId)." -ForegroundColor Green
    } catch {
        Write-Error "Could not delete '$($group.DisplayName)': $($_.Exception.Message)"
    }
}
.\Remove-EntraGroup.ps1 -GroupId 3f2a6b1c-0d4e-4f5a-9b8c-7d6e5f4a3b2c

The script looks the group up, shows its name and asks you to confirm. -WhatIf shows what would happen; -Force skips the prompt. To undo a whole test import, feed it the ID map (try it with -WhatIf first):

Import-Csv .\groups-id-map.csv | ForEach-Object { .\Remove-EntraGroup.ps1 -GroupId $_.NewId -Force }
Deleted Microsoft 365 groups can be restored for 30 days from Deleted groups in the Entra admin centre. Treat any other kind of group as gone for good.
